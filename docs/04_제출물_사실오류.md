## 2. ⚠️ `AgentShield.RuntimeGuard` — 어댑터 이름과 실체의 혼동

**문서 기재** (5곳: `00_조사노트.md:65`, `01_MVP제안서.md:323`, `02_기술명세서.md:73/395/708`):

조사노트 A-5는 이를 *"AITHOR-Agent-Framework 재사용 자산 (파일 직접 열람)"* 으로 표에 올린다.

**실측**:

| | 문서가 시사하는 것 | 실제 |
|---|---|---|
| 실체 | `AgentShield` 제품의 RuntimeGuard | `aithor_agent_framework.guard.RuntimeGuard` |
| docstring | — | *"Standalone deterministic guard **inspired by** AgentShield RuntimeGuard"* |
| 관계 | 동일물 | **별도 구현** (영감을 받은 재구현) |

`AgentShield`는 실재하는 별도 저장소(`Aithor-organization/AgentShield`, private)이나
**이 프로젝트는 그것을 쓰지 않는다.** 프레임워크 내장 `guard.RuntimeGuard`를 쓴다.
workflow.yaml의 `adapter: AgentShield.RuntimeGuard`는 **어댑터 이름 문자열**일 뿐이다.

**실제 공개 API** (실측):

```python
from aithor_agent_framework.guard import RuntimeGuard, GuardPolicy
g = RuntimeGuard()
# inspect_input / inspect_output / authorize_tool / audit_event / policy
```

### 왜 고쳐야 하나

*"AgentShield를 씁니다"* 라고 말한 뒤 코드에 `aithor_agent_framework.guard`가 나오면
심사위원은 **다른 두 시스템을 하나로 말한 것**으로 읽는다. 이름만 바로잡으면 되는 문제다.

## 3. ⚠️ `AITHOR-Agent-Framework` 로컬 부재 — "파일 직접 열람" 근거의 재현 불가

조사노트 A-5는 프레임워크 자산 8종을 *"파일 직접 열람"* 으로 표기한다. 그러나 이 저장소를
받은 사람의 머신에는 프레임워크가 없다 — GitHub private 저장소에만 있고 clone 지시가 문서에 없다.

**조치**: 본 세션에서 클론하고 `README`에 의존 관계를 명시한다.
재현 경로가 없는 "직접 열람"은 심사에서 **미검증 주장**과 구별되지 않는다.

```bash
gh repo clone Aithor-organization/AITHOR-Agent-Framework
# 설치 불필요 — sys.path 에 src/ 만 추가하면 import 된다 (실측)
```
